# TappaScore Full-Stack Deployment Guide

This guide provides instructions and architectural specifications for deploying the TappaScore full-stack application to production.

---

## 1. Architecture Overview

TappaScore follows a modern decoupled full-stack architecture:

- **Frontend**: React 18 + TypeScript + Vite + TailwindCSS build artifact output to static HTML/JS/CSS (`dist/`).
- **Backend API**: Node.js + Express (ES Modules) handling REST API endpoints, session authentication (JWT), and owner portal operations.
- **Real-time WebSockets**: Socket.IO integrated with Node HTTP server for real-time live scoring broadcasts and in-app notifications.
- **Database**: MongoDB Atlas with Mongoose ODM storing users, matches, reviews, owner activity logs, and notifications.
- **Security**: 24-hour HMAC-SHA256 JWT tokens, scrypt password hashing with unique 16-byte salts, single-owner architecture with single-instance bootstrap protection, and 15-minute login lockout after 5 failed attempts.

## 2. Environment Variables (NAMES ONLY)

> ⚠️ **SECURITY WARNING**: Never commit actual secret values to git or expose them to the frontend bundle.

### Frontend Environment Variables
| Variable Name | Required | Purpose / Description | Example Value Pattern |
| text | YES | Base URL for API requests (if hosted on separate domain) | `https://api.tappascore.com` |
| `VITE_SOCKET_URL` | OPTIONAL | Socket.IO server URL (defaults to origin if reverse-proxied) | `https://api.tappascore.com` |

### Backend Environment Variables
| Variable Name | Required | Purpose / Description |
| text | YES | HTTP server port for Node.js Express backend |
| `NODE_ENV` | YES | Deployment environment mode (`production`) |
| `MONGODB_URI` | YES | MongoDB Atlas connection string |
| `JWT_SECRET` | YES | Cryptographic secret for signing JWT tokens |
| `CORS_ORIGIN` | RECOMMENDED | Comma-separated list of allowed frontend origins |
| `OWNER_BOOTSTRAP_NAME` | ONE-TIME | Full Name for initial Owner account creation script |
| `OWNER_BOOTSTRAP_EMAIL` | ONE-TIME | Email address for initial Owner account creation script |
| `OWNER_BOOTSTRAP_PASSWORD` | ONE-TIME | Initial password for Owner account creation script |

## 3. Frontend Deployment Requirements

- **Build Output**: Static SPA files generated by `npm run build` in `/dist`.
- **Hosting Options**: Vercel, Netlify, Cloudflare Pages, AWS S3 + CloudFront, or Nginx.
- **SPA Routing**: Configure static server rewrite rules so all unmatched routes fallback to `/index.html`.
- **API & Socket Proxy**:
  - If frontend and backend share a domain via reverse proxy (e.g. Nginx/Caddy), proxy `/api` and `/socket.io` to the Node.js backend.
  - If frontend and backend are on separate domains, set `VITE_API_BASE_URL` and `VITE_SOCKET_URL` build variables.

---

## 4. Backend Deployment Requirements

- **Runtime**: Node.js v18.x or v20.x LTS.
- **Hosting Options**: AWS Elastic Beanstalk, Render, Railway, Fly.io, DigitalOcean App Platform, or Docker VPS.
- **Process Manager**: PM2 or container orchestra (`npm start`).
- **Health Check Endpoint**: `GET /api/health` returns HTTP 200 with DB connection status.

---

## 5. MongoDB Atlas Requirements

1. **Database Cluster**: Create a MongoDB Atlas M0 (Shared) or M10+ production cluster.
2. **Network Access**: Add backend IP addresses (or `0.0.0.0/0` for auto-scaling PaaS hosts) to MongoDB IP Access List.
3. **Database User**: Create a dedicated database user with `readWrite` permissions on the `tappascore` database.
4. **Indexes**: Verified Mongoose schemas will automatically create unique index on `User.email`, `Match.matchId`, `Match.numericMatchId`, and single field indexes on foreign keys.

---

## 6. CORS & Socket.IO Production Configuration

- **CORS Setup**: Specify frontend domain(s) in `CORS_ORIGIN` (e.g. `https://tappascore.com,https://app.tappascore.com`).
- **Socket.IO Transport**: Support both `websocket` and `polling` transports. Ensure sticky sessions / WebSocket upgrades are allowed by load balancer if running multiple backend nodes.

## 7. Owner Bootstrap Instructions

The Owner Portal enforces a **strict single-owner architecture**.

1. Before starting application traffic, set `OWNER_BOOTSTRAP_NAME`, `OWNER_BOOTSTRAP_EMAIL`, and `OWNER_BOOTSTRAP_PASSWORD` in `backend/.env`.
2. Run the bootstrap script:
   ```bash
   cd backend
   npm run bootstrap:owner
   ```
3. The script creates the initial Owner account (or promotes existing email user to Owner) and outputs the Owner User ID.
4. Once created, subsequent executions of `bootstrap:owner` are **permanently blocked** by database role inspection.
5. The Owner can manage account details (Name, Email, Password) securely via `/owner/account`.

## 8. Post-Deployment Smoke Tests Checklist

- [ ] `GET /api/health` returns `{ "status": "ok", "database": "connected" }`.
- [ ] Registered user login and token persistence working cleanly.
- [ ] Create a match, record deliveries, and verify 8-digit numeric match ID generation.
- [ ] Open `#live-<numericMatchId>` on a second window/device to test public read-only Socket.IO updates.
- [ ] Complete match and verify scores and deliveries become permanently locked.
- [ ] Navigate to `/owner/login` and verify Owner login succeeds.
- [ ] Attempt 5 consecutive invalid Owner logins and verify 15-minute lock error response.
- [ ] Verify Owner Portal user list, match detail inspection, review moderation, and activity log entries.
- [ ] Verify player career stats derive exclusively from completed matches and respect privacy settings.

---

## 9. Rollback Considerations

- **State Persistence**: Match state is synced to MongoDB. Database backups (MongoDB Atlas continuous backups / snapshots) should be taken before major database migration scripts.
- **Stateless Backend**: Backend nodes are stateless and can be rolled back to previous container image tags instantly.
- **Frontend CDN Cache**: Purge CDN edge caches (Cloudflare/Vercel) when redeploying static assets.
